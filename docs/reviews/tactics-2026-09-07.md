## Registered interfaces

| Family | Change and contract | Evidence |
|---|---|---|
| `gcongr` | Register `wp_mono_of_support`; retain `wp_mono` at low priority. | A production hiding proof now stays in the public `wp` interface. Tests check support binders, finite sums, and unrestricted hypotheses. |
| `finiteness` | Register finite-result expectation and `wp` lemmas, requiring pointwise finite values. Provide an explicit finite-bound expectation helper. | Ordinary-import tests cover composition, local abbreviations, missing hypotheses, and infinite result types. |
| `fun_prop` | Register concrete `Option.map`, `Option.elim`, and `Except.map` heads. | Three measure proofs simplify; nested optional/exception observations work on arbitrary measurable spaces. |
| `positivity` | Add a `tvDist` extension using its public nonnegativity theorem; export through the program-logic tactic import. | Eight simulation proof sites simplify. Tests distinguish nonnegativity from strict positivity and nonzero distance. |

The finite-result rules do not assume that arbitrary expectations are finite. They work for
subprobability semantics and do not introduce nonempty or losslessness hypotheses. The bound helper
keeps the bound explicit. No new global `simp`, `grind`, `ext`, `vcspec`, or `wpStep` registrations
were justified by the selected consumers; those families remain part of the standing review scope.

## Follow-up backlog

1. **Integrate #515's expectation API after its toolchain/prerequisite update.** Its head predates
   the shared registrations and overlaps the newer expectation module. Reconcile that API once,
   then revisit its expectation/bind bounds with support-aware congruence. Keep integration and
   proof simplification in separate commits.
2. **Normalize exception matches for `fun_prop`.** `Except.map` composition works, but an ordinary
   exception `match` can elaborate to a generated matcher head that a `casesOn` registration does
   not recognize. Reproduce with arbitrary measurable spaces and measurable error/success
   branches; the residual goal is measurability of the whole match. Prefer an explicit public
   eliminator interface before changing tactic unfolding globally.
3. **Improve discovery of explicit normalization steps.** Raw `Std.Do'.wp` comparisons need
   `change OracleComp.ProgramLogic.wp ... ≤ ...`; a hidden local probability abbreviation can need
   `dsimp only` before `finiteness`. The working scripts are documented and compiled. A future
   suggestion should emit those scripts and have an ordinary-import replay test.
4. **Extend finite-expectation automation from finite types to finite support or supplied bounds.**
   Pointwise finiteness on an infinite result type leaves `expectedValue mx g ≠ ⊤` unresolved,
   correctly. Any extension needs explicit domination/support evidence and a real consumer.
5. **Continue the broad attribute audit through new PRs.** Check `simp`/cast normal forms,
   extensionality, and `vcspec`/`wpStep` discovery with changed consumer proofs. Require a concrete
   failed goal before adding registrations; in particular, keep unrestricted `Measurable f`
   eliminator theorems out of global `fun_prop` search and avoid quantifier-expanding loops.
