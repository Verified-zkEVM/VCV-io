The main reductions use existing expectation linearity and support-aware bounds. Rewriting
`wp_eq_expectedValue` and `← expectedValue_finsetSum` removes hand-written finite-sum induction;
`expectedValue_le_of_support` removes repeated splits on zero output mass. Existing `gcongr`
registrations handle monotonicity while `omega` and `exact_mod_cast` discharge the remaining
counter arithmetic. The natural subtraction in the counter-total argument uses
`Finset.sum_tsub_distrib` with the existing counter-monotonicity proof.

The handler proofs normalize cache branches with `simp_all`, then expose tuple projections
before `omega`. Finite-support equality starts with `ext`. The encoding proof uses constructor
injectivity, a controlled `simp_all only` normal form, and list length. The rounding proof casts
`Nat.div_add_mod` directly. These changes exercise library algebra, simplification,
extensionality, and arithmetic beyond the congruence tactic.

## One effective registration

`OracleComp.EvalDist.expectedValue_map` gains `@[simp]`. Its normal form is an expectation of
the original computation with a precomposed payoff; it does not expand expectations into sums.
The theorem retains its generic lawful subprobability-lift assumptions, with no support
semantics, losslessness, nonemptiness, or finite-result requirement.

Two production consumers each shrink from three lines to one:

```lean
-- OracleComp.ProgramLogic.wp_map
simp [wp_eq_expectedValue, Function.comp_def]

-- ProbComp.expectedValue_length_cons_map
simp [expectedValue_add, expectedValue_const (probFailure_of_liftM_PMF mc)]
```

An ordinary-import probe compiled before registration with
`fail_if_success solve | simp`, followed by an explicit application of `expectedValue_map`.
`VCVioTest/Tactic/Expectation.lean` checks ordinary `simp`, nested maps, finite sums, and an
empty SPMF result type. Its negative probe removes just `expectedValue_map` and checks that
the generic goal remains. Separate whole-module probes disable the rule in each of the two
shortened production scripts to verify that both actually use it.

No removed #659 attribute is restored. This round adds no tactic command, tactic implementation,
global bind-to-sum simplification rule, or other registration.

## Rejected candidates and usable boundaries

- The seven-line candidate for
  `sum_wp_countIncrementIndicators_le_queryBound_of_run_hidingImplCountAll` made its existing
  `[Finite M]` parameter unused. The environment linter caught this. Its original proof is
  retained to preserve the public signature without adding a suppression or an artificial use
  of the instance. It is excluded from the ledger.
- Unrestricted `grind` on the counter-handler support goals exhausted the default heartbeat
  budget. Explicit handler normalization followed by projection reduction and `omega` was
  short and predictable; no heartbeat limit was raised.
- Bare `gcongr` on a `wp` comparison descended into the finite sum beyond the next available
  bound. `gcongr (OracleComp.ProgramLogic.wp _ (fun _ => ?_)) with x` leaves the whole sum
  as the intended obligation.
- Broad nonterminal `simp_all` in the encoding proof triggered the flexible-tactic linter.
  The accepted script uses the suggested explicit rule set before the length argument.
- `simp` alone did not close the vector identity in `decodeExact_encode`; its existing short
  proof remains. A blanket `aesop` replacement for finite-support equality also failed until
  extensionality exposed element membership.

## Follow-up priorities

1. Generalize the indicator-count bound in a separate API change that removes the redundant
   `[Finite M]` parameter and updates its callers. The shorter candidate is useful evidence for
   that generalization, but changing a public signature is outside this cleanup batch.
2. Extend the support-aware expectation review to query-cost and reduction bounds. Start from
   repeated `wp_eq_tsum` / zero-mass case splits and require compiled production replacements
   before proposing a shared bridge or another registration.
3. Revisit `vcspec` / `wpStep`, `finiteness`, `fun_prop`, and `positivity` at new consumer sites
   after their prerequisites merge. The previous round already supplied registrations in several
   of these families; new attributes need fresh ordinary-import evidence. Keep the direct vector
   round-trip proof unless a simpler canonical interface also benefits other consumers.
